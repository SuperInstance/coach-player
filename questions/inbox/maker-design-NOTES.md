# Maker Lane — Design Analysts family: mining notes

15 questions (design-001 to design-015), all hypothesis grade with
`winner_lean: null`. Transcripts are temporarily unavailable (API
plan), so nothing here is shaded yet — each question's
`evidence_needed` names the analyst channels whose timestamped
segments would settle it: Jack Sather, Game Design Library, The Game
Overanalyser, Indie Game Clinic, Tesseract.

Stance note: unlike the Show/Coach lanes, these questions shade a
*game* (or the avatar's reading of a game), not a performer. Their
discriminating test is whether two good games — or two analysts
reading the same game — land at meaningfully different places, and
whether the answer changes how the avatar reads, talks about, or
commits to a new game.

## Top 5

1. **design-005 — watchability as a design property** (fun in the
   hands vs fun legible to a watcher). Coach Player is a watched
   product, so this is the most product-critical question in the
   family: it grades a game *before* a session is committed to it.
   Wide spread expected — execution-heavy games and readable-state
   games are both successful and sit at opposite ends.
2. **design-007 — the load-bearing trick** (fun spread thin vs one
   number/timer/scarcity/physics edge carrying the game). This is
   the fastest game-reading skill the avatar can have, and it is
   nudgeable: a coach can order "find the trick first" as a reading
   priority. It also tells the coach where nudges will actually
   bite.
3. **design-003 — teaching without tutorials** (explicit instruction
   vs designed first encounters). The avatar coaches a kid the way
   the game teaches the avatar: arrangement versus recitation is a
   real, observable split between successful games, and it doubles
   as the curriculum's mirror.
4. **design-002 — difficulty honesty** (readable threats vs hidden
   punishment). Calibrates what the avatar says after a death —
   analyse the lesson, or name the death as noise. Analysts argue
   this axis hard over the same games, which is exactly the
   discrimination signal the shading test wants.
5. **design-010 — diagnosis depth** (fix the numbers vs fix the
   structure). The "what would a designer change and why" question,
   made shadeable: Indie Game Clinic-style advice separates cleanly
   into tuning notes and redesigns. It gives the avatar's debriefs
   — and the kid's second-year questions — a depth dial.

## Dropped as flat (and why)

- **"Is this game good?"** — a verdict, not a spectrum. Returns the
  analyst's taste, not an observable property; Jev on it collapses
  toward 50 across the field. Quality is what the other 15 questions
  decompose.
- **"Does the game respect the player's time?"** — every analyst
  shades it the same righteous direction; it describes a virtue
  claim about the medium, not a difference between games. Fails the
  discriminates test.
- **"Is the game innovative or derivative?"** — a binary wearing a
  spectrum's clothes; analysts split on the definition, not on
  observations. Replaced by design-015 (where the novelty *lives*:
  drip-fed mechanics vs recombination), which is checkable against
  a game's actual content schedule.
- **"How hard is the game?" (absolute)** — player-relative and
  mushy; judgments land at 50 for opposite reasons. Split into
  design-002 (is the difficulty honest) and design-012 (what scales,
  execution or understanding), which separate cleanly.
- **"Does the game look good?"** — a rendering/medium property;
  the visual track already owns the picture. No avatar behaviour
  changes with the answer.
- **"Would a designer change this game?"** — unfalsifiable as
  asked; nobody shades "no" on a game they chose to analyse.
  The locatable, evidence-bearing version is design-010.

## Deliberate non-duplicates

- design-004 (authored vs emergent *game* moments) is the maker
  twin of the performer spectacle question (engineered vs harvested
  *show*): one shades the game's design, the other the performer's
  sourcing. Both earn their place — a game can be emergent while a
  performer scripts it, and vice versa.
- design-009 (the game's failure price list) pairs with the
  performer stakes questions the same way: the game's real price
  is the ground truth the avatar's stake narration must match.
- design-013 (designed valleys) is about what the game built, not
  what a performer does during downtime; the existing downtime
  questions shade the performer.
